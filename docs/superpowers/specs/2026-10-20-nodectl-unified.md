# 妙妙屋X / NodeCTL 统一后台

## 目标和架构

管理员只登录妙妙屋X一次，从原页面侧栏管理 NodeCTL 的服务器、Agent 和协议。可选 Node.js 网关代理妙妙屋X并注入同源管理扩展，不修改上游二进制，不嵌入第二个登录页面。

每次管理请求将原 `traffic_info_access_token` 交给妙妙屋X的 `/api/user/profile` 校验，必须明确返回管理员身份。不另建长期管理会话。网关只读 NodeCTL SQLite 的当前签名密钥和管理员名称，签发仅存在于服务端请求中的一分钟 JWT。NodeCTL 自己处理数据库写入和 Agent 操作。

## 数据和功能边界

- 展示已有服务器、Agent 版本、地址、流量与协议；支持新增、编辑基本信息、删除和生成原生 Agent 安装命令。
- 使用原生接口启用、停用、重置协议；危险操作须在界面确认。
- 支持导出链接，以及显式调用妙妙屋X原生加密客户端新增缺失节点。按原链接去重，不改旧节点、标签和订阅令牌，不自动删除记录，不宣称双向自动同步。
- 保留妙妙屋X原有节点和订阅管理，以及旧 Agent 域名、安装关系。新部署透传四个明确的 Agent 公开入口及 WebSocket，验证仍由 NodeCTL 完成。
- 不直接写业务数据库，不提交生产配置、密码、数据库或令牌。初版 NodeCTL 仅支持 SQLite。

## 安全、部署与回退

管理 API 采用操作白名单、请求体上限和同源 Origin 加自定义请求头校验，不返回上游 JWT、隧道密钥或异常堆栈。普通订阅的字节、查询参数和状态不变。原生导入适配器限定已验证的 0.5.4 API，不兼容时停止导入。

提供新装三服务 Compose 和仅接入现有服务的 Linux host-network Compose。旧 systemd 安装器不变。本次只更新 GitHub，不自动切换生产。将来接入 JP 时新增网关并只切换 Caddy upstream；回退恢复原 upstream，无数据库迁移。

## 验收

测试覆盖当前登录校验、撤销、权限、CSRF、路由白名单、短期 JWT、只读 SQLite、更新字段保留、订阅原样代理、导入去重。浏览器测试验证原侧栏和主内容区、一次登录、编辑、协议管理、退出恢复与恶意文本转义。生产核查只读，不以测试通过代替上线验收。
